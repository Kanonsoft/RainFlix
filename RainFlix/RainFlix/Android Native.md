# Android Native

Launcher and Android 12+ launch screens use the bundled R centered on an opaque dark tile (`#08111F`), matching the startup loader. The foreground artwork stays transparent; the launcher background no longer is. Android 8+ uses an adaptive icon with explicit dark background and centered R, while older launchers use the dark layer-list fallback. The HTML pre-module fallback also shows R with an animated progress bar; failure messages and Reload remain available if startup fails. Android launchers may still impose their own icon mask. The catalog uses its dark launch theme to prevent a light flash before the React loader mounts.

Related: [[Title Playback]], [[Native Torrent Desktop]], [[Add-ons]], [[Downloads]].

The Android Tauri build shares the React catalog, title pages, add-on installation, My List and Continue Watching with Windows. Vite's `mobile` mode writes `dist-mobile`; app navigation includes Add-ons and hides the website download action. The Windows mpv executable and named-pipe code are excluded from Android builds.

## Playback

The Android controls follow the desktop visual hierarchy: title/back at the top, a circular-thumb seek bar below, bottom playback actions for pause, seek, speed, audio, subtitles, episodes and settings, and a right-side season/provider/stream drawer. Mobile uses hardware volume keys. Touch targets are at least 48dp. Track panels are dark, dismiss outside, and use readable language names. This is shared styling and behavior where supported, not identical mpv capabilities. Main catalog content respects system-bar and display-cutout insets; trailer/frame playback temporarily requests landscape and restores portrait on close.

Mobile cards fit three columns, with compact metadata. Search/browse pagination uses an IntersectionObserver and ghost cards; failed subsequent pages expose Retry instead of an automatic retry loop. Text search now retains TMDb page counts and fetches subsequent result pages. The startup fallback keeps error recovery but does not flash a Starting RainFlix message. Stream lookup uses neutral placeholders rather than a second title-logo loader.

`src-tauri/plugins/native-player` supplies an in-app landscape Android Activity using AndroidX Media3 ExoPlayer. Selecting an authorized stream opens it immediately, showing title artwork, the title logo (or the bundled RainFlix R), and horizontal startup buffer progress. Torrent metadata may still take up to 75 seconds. Back returns to RainFlix; audio is paused when leaving the player for another app. Playback does not use Stremio Service or a separate video app.

The player provides pause, seek, playback speed, language-grouped embedded subtitle/audio selection, add-on subtitles, and a scrollable season/episode/provider/source drawer. Native events use the existing progress and per-title preference flow; Continue Watching begins on actual playing, not lookup or metadata readiness. Next/previous and EOF use the existing fresh same-provider episode resolution. Manual episode selection opens provider/source choices instead. URLs and responses remain in memory, not history storage.

Play/pause and five-second seek actions stay in the bottom toolbar. Title/back visibility follows the same controller timer. Volume uses Android's hardware buttons, not a player slider. Audio/subtitle panels show languages first, then that language's embedded and add-on variants. Subtitle appearance offers size, bottom padding, background and embedded styling; explicit positioning in embedded ASS cues may override bottom padding. Appearance choices travel through the existing per-title preferences. The episode drawer has no search field and dismisses on an outside tap. Provider rows use add-on logos with an R fallback; source rows separate headings, quality badges and full release details with dividers.

Android decoding uses the device's supported codecs with decoder fallback. MP4, WebM, supported MKV tracks, HLS and DASH are supported by Media3, but this is not the Windows bundled mpv/FFmpeg codec set. DRM, unavailable peers, unsupported device codecs, unusual containers, request-header requirements and live add-on failures can still prevent playback. Casting is not implemented. Do not describe the builds as full feature parity.

Buffering uses a single horizontal indicator: animated indeterminate progress during metadata discovery, then measured progress toward five seconds of buffered media. No secondary circle spinner is shown. Intro/outro actions require supported container or ID3 chapter markers with timing metadata; absent markers mean no manual or automatic skipping. There are no estimated intro/ending durations, and source changes clear prior chapter markers. Automatic skipping is off by default. Settings controls skipping, preview, prefetch and automatic next. The next-episode card appears in the last 45 seconds when the next episode is known.

A single tap on the video toggles the full controls, including the title/back row. Double-tap seeking and center playback controls are removed; bottom seek buttons and the timeline remain. When paused, the center displays the title logo without a pause icon.

Player popups use compact widths (330dp for tracks/settings, 260dp for speed) and scrollable, content-sized track lists. Speed uses a two-column grid. Subtitle settings is a header action alongside Subtitles, not an item mixed into the language list. RainFlix Settings also provides shared subtitle appearance defaults and a sample-image preview; see [[Settings]].

Compressed ASS subtitle packets must remain binary until decompression. `RainFlixExtractorsFactory` substitutes a narrowly patched copy of Media3 1.11.1's `MatroskaExtractor` (Apache 2.0, copyright/header retained) for MKV only. `RainFlixMatroskaExtractor.java` preserves zlib ASS packets rather than truncating at an interior NUL, and permits explicit zlib encoding only for ASS/SSA. All other formats continue through Media3's stock extractors. Upstream source: https://github.com/androidx/media/blob/1.11.1/libraries/extractor/src/main/java/androidx/media3/extractor/mkv/MatroskaExtractor.java. Review/rebase this file when changing Media3 versions; do not silently drop the patch. `MatroskaSubtitleTest` exercises the entire extraction path with three compressed dialogue packets containing interior zeros, then produces `android/build/compressed-subtitles.mks` for the Windows decoder check. Missing dialogue in an incomplete/incorrect subtitle track is still a source limitation; no text is guessed from speech.

Subtitle and audio rows indicate the currently selected track. External subtitle content is identified as SRT, WebVTT or ASS rather than guessing from a URL extension. Compressed ASS dialogue packets are inflated with a 1 MiB per-packet cap before parsing, retaining container timing. Invalid packets are not treated as successful subtitles. Subtitle settings include delay, size and vertical position. The player settings panel controls automatic intro/outro skipping, next-episode preview and preload. Media3 container chapter metadata (including supported MKV/MP4 chapters) and ID3 chapters provide real skip intervals; no estimated timings are used.

Previous/Next controls are visible only when the ordered episode metadata contains a neighbor for the currently playing episode. They refresh when episode metadata arrives or changes, follow known cross-season neighbors, and both stay hidden if the current episode is missing from the list. Button navigation and the next-episode preview use the same neighbor lookup.

Android torrent prefetch starts after current playback is ready with five seconds buffered. Shared episode resolution keeps the same provider and matching release preferences. A separate low-priority torrent reads up to 4 MiB at the beginning and 512 KiB at the end, then pauses. This is byte prefetch, not a promise of five decoded seconds. Handoff requires the same magnet and file index; unavailable peers or a failed handoff use fresh playback. Unclaimed warm sessions expire after two hours and claimed handoffs after 90 seconds. Player exit/background cancels unclaimed prefetch. No background Android torrent service is installed.

The Up next card displays remaining playback time and invokes the same next-episode action as the bottom button. EOF reports its known next ID and automatically advances when enabled; the final episode returns to the series page. Failed lookups release the navigation latch and open retryable source selection instead of trapping navigation. Unknown IMDb season IDs load their season metadata before resolving sources. Artwork updates no longer restart an active native session. The catalog WebView is resumed while the native RainFlix player is foreground so stream lookup, subtitle requests and prefetch callbacks remain active; it is paused again when the player backgrounds. This is not permission for background torrent playback.

`src-tauri/src/android_torrent.rs` embeds librqbit with Rust TLS. It selects only the requested file (preserving zero-based indexes) or the largest recognized video. Normal BitTorrent TCP/UDP peers and DHT are supported. A tokenized read-only GET/HEAD byte-range endpoint binds only to loopback. One session is active; replacement waits for cancellation/cleanup. Temporary files are owned by UUID-named playback folders under app cache; normal stop removes them. Crash cleanup is not yet implemented. Metadata/storage initialization have bounded deadlines, files are capped at 12 GiB, peers at 40, and upload at 256 KiB/s. Playback should be foreground-only; there is no background torrent service.

## Install Links

The player Activity uses a translucent window with a fully opaque black video root, keeping the underlying catalog WebView visible to Android for provider and prefetch callbacks. It inherits landscape from the host rather than requesting a fixed orientation itself (Android 8 translucent-Activity compatibility). Exit restores the host orientation. The bridge WebView resumes while the player is foreground and pauses when it backgrounds. Episode selection shows providers before requesting streams, preserving the episode -> provider -> sources flow independently of the title page's provider-first flow.

Mobile listeners must deserialize a typed `tauri::ipc::Channel<Value>` in the Rust `register_listener` command before forwarding it to Kotlin. Forwarding only the raw JSON callback identifier does not register Tauri's mobile channel, silently dropping playback/close/install-link events and eventually triggering the frontend startup timeout even while video plays.

The main Activity declares `stremio://` and `rainflix://` intent filters. The native plugin validates a provider-independent HTTP-style host and `/manifest.json` path, rejects credentials/fragments and keeps the incoming link in memory. Cold and warm links open Add-ons with the manifest filled in; the user must still press Install. No configured manifest URL is logged or written to the route. Android chooses the handler: if Stremio is installed or already set as default, the user must choose RainFlix or clear that association themselves. RainFlix does not override another app's defaults.

## Build

Release builds must include Android's `proguard-android-optimize.txt` defaults and the Jackson enum reflection rules in `app/proguard-rules.pro`. Without these, R8 removes `SerializationFeature.values()`, causing Tauri's PluginManager/ObjectMapper initialization to crash before React starts. Debug builds do not reproduce this because minification is disabled. Always verify a signed release launch as well as debug playback.

1. Install Android Studio, SDK platform/build tools 36, NDK and Rust Android targets.
2. Run `npm run android:init` only for initial project setup. The checked-in Android project includes custom configuration; do not regenerate it over edits.
3. Run `npm run android:build` for a signed ARM64 release APK, or `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/android.ps1 -Action build -Debug` for device verification.
4. APKs are under `src-tauri/gen/android/app/build/outputs/apk/arm64/`.

The helper discovers Android Studio's JBR and installed NDK without changing persistent environment variables. On Windows without symlink permission it copies the successfully compiled native library and runs Gradle with that already-built Rust task excluded; it does not enable Developer Mode or elevate permissions. First builds can download substantial Rust/Gradle dependencies.

Release signing creates a private local `rainflix-release.jks` and `keystore.properties` on the first release build. Back up both together for future updates; they are gitignored. Never regenerate the key for an already distributed application. This is an APK build, not a Play Store publication or website release upload.

Device verification uses an explicitly selected `adb -s <serial>` target. The user must allow installation via USB and accept the phone's install prompt. Do not clear app data, uninstall apps or change default link handlers to make tests pass.
