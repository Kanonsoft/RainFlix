# Add-ons

Native builds seed `RAINFLIX_CONFIG.nativeDefaultAddons` on first use: Torrentio (10 GB filter), TorrentsDB, AnimeSub, Subsense, and the configured streaming-service catalog. Duplicate addresses install once. Successful seeds are recorded in IndexedDB separately from registrations, so uninstalling a default keeps it removed; unavailable defaults retry next launch. Disabled installed providers are not re-enabled. Manifests and stream responses remain fetched fresh, not persisted. Installing stays on the current tab; Installed cards show descriptions with the same styling as Browse cards.

Installed add-on artwork uses `src/lib/addon-logos.js`: seven-day IndexedDB raster snapshots, shared in-flight requests and an R fallback. Cache keys are SHA-256 hashes, not manifest URLs or query credentials. Only image data and expiry are persisted, never stream results. Native provider drawers receive cached bounded PNG data where available; inaccessible image hosts fall back to normal image loading. Clear cache also removes these logo snapshots.

Related: [[README|RainFlix Notes]], [[Architecture]], [[Configuration]].

Web builds install configured `webDefaultAddons` when absent. The default is the user's stream-only Yastream manifest (KissKH and OneTouchTV, no catalogs). Registrations use the same private IndexedDB storage and are deduplicated by manifest URL; disabled installed defaults are not silently re-enabled. Windows and Android do not auto-install web defaults. Manifest startup is limited to five seconds and fails independently of the TMDb catalog. Stream lookups and source authorization still use the shared provider flow; no media plays merely because a default was installed.

Add-ons navigation is app-only: Header and the mobile drawer hide it in ordinary web builds, including phone browsers. The existing `desktop` build shows it, and the reserved future `mobile` build mode will show it too. This is navigation visibility, not a security restriction: the private/testing `/addons` route and installed add-on behavior remain intact. It does not create or package a mobile app.

The `/addons` route separates the community directory and installed management into Browse (default) and Installed tabs. The manifest install form remains available in both; successful installation opens Installed. Switching tabs preserves directory search, category and pagination. Tabs support arrow keys, Home and End. Installed cards remain compact without descriptions; directory cards show descriptions and Install/Configure controls, with search, category filtering, pagination, loading and Retry. The outbound directory-site link and plain-text directory attribution are removed. `src/components/AddonDirectory.jsx` reads the existing stremio-addons.net public API with no-store requests and cancels stale searches. Directory failures do not disable manual installation or installed add-ons. Header and mobile navigation place My List after Browse, with Add-ons last when app navigation is enabled.

Yastream and Torrentio are disabled by default in configuration. Their legacy adapters are retained for explicit opt-in and regression coverage. Installation is available through any HTTP(S) or stremio manifest link. Configurable add-ons open their own configuration page.

## Website Install Links (Windows)

The installer also registers a RainFlix-specific ProgID and per-user Windows application capabilities for both protocols. RainFlix is selectable under Windows Default Apps even when Stremio is already registered; existing defaults and `UserChoice` are never overwritten. Select RainFlix for the STREMIO link type if another application currently handles it. Reinstall the new installer to apply these registrations. Uninstall removes RainFlix-owned capabilities only when the registered executable still matches that installation.

Valid `stremio://` and `rainflix://` anchors clicked inside the native app are handled directly through the same automatic manifest installation flow, without relying on OS default handlers. Malformed custom-protocol links are intercepted but rejected without navigation. Android website link handling is documented in [[Android Native]].

Install the rebuilt Windows installer to register `rainflix://` and, only if no command/default handler already exists, `stremio://`. This is generic: `stremio://addon-host/configuration/manifest.json` and `rainflix://addon-host/configuration/manifest.json` are converted to HTTPS manifest addresses, independent of provider name. Torrentio's Configure page uses this format. Existing Stremio/other handler associations are not overwritten. Windows uses one handler per protocol; this is not a browser-side installed-app detector, and a stale existing association may still need the user to repair Windows defaults. Browser confirmation prompts still apply. Static web pages cannot receive these OS links by themselves.

Cold launches read validated CLI arguments. Subsequent launches are forwarded through the Tauri single-instance plugin, focus the existing window, and open Add-ons. `src/lib/addon-install-links.js` keeps a pending link in memory; entering through an explicit browser install link starts manifest installation immediately and selects Installed on success. Manual manifest input remains available for retry. A newer explicit install link cancels an older pending installation. Credentials never enter the route, logs, localStorage, or service worker; configured registrations remain in private IndexedDB as described below. Only HTTPS manifest endpoints are accepted through external links, with no URL credentials, fragments, or arbitrary commands. Manual input still supports existing HTTP(S) manifests. Uninstall removes only associations pointing to this RainFlix installation. Development builds do not change registry associations.

Protocol hooks: `src-tauri/installer-hooks.nsh`; argument bridge: `src-tauri/src/lib.rs` and `src/platform/desktop.js`. No remote add-on code is executed.

Installed registrations (stable ID, configured manifest address, enabled state and display name) persist in IndexedDB `rainflix-private/settings`. Manifests are fetched fresh at startup, never persisted in that database. Existing tab-session registrations migrate automatically. Offline registrations remain installed and are retried next launch. Configured links can contain credentials: this private-testing storage is not encrypted. They are never copied to localStorage or the service worker. Lookup responses and media URLs remain memory-only.

Playback positions are separate from installation storage. Built-in TMDb/IMDb titles retain per-episode timestamps on this device across visits and stream/provider changes where seeking is supported. Custom add-on identities also retain bounded per-episode progress; only IDs and numeric progress are stored. No stream URLs or manifest credentials are copied into the position history. See [[Title Playback#Playback Positions]].

`src/lib/addons.js` owns installation, removal, enablement, manifest resource filtering, and generic stream/subtitle requests. Matching providers are queried for availability; only providers returning streams appear under Streams, with loading and retry states. Availability lookup never starts a media transfer. String and object resource declarations are supported. Multiple streams wait for source selection; a sole playable result starts after the provider click; torrents retain their file index and existing WebTorrent/Stremio/external modes. External HTTP links open the provider. Uninstalling or disabling a provider unmounts its player.

Enabled catalog add-ons contribute independent rows on Home with Browse catalog links, but only after returning at least one valid title. Pending, empty, invalid, failed, and input-only catalogs render no Home section, heading, skeleton, or empty-state message. A hidden row does not disable or uninstall its add-on. Installed add-on cards show management controls without individual catalog links. Dedicated `/addon/:addonId/catalog/:type/:catalogId` pages use the declared catalog extras, including search, genre, custom required fields, and skip pagination. Required fields gate requests; search-only catalogs are not fetched on Home. Filters and paging are in the hash route query so Back restores them. Catalog failures remain isolated; dedicated catalog pages retain their error/retry controls and empty states.

`src/lib/addon-catalogs.js` normalizes catalog previews and metadata without coercing custom IDs to TMDb numbers. A bounded memory-only preview map allows catalog-only cards to open basic details. Catalog responses, preview details, and embedded media URLs are not persisted. IMDb movie/series IDs in the last route segment can resolve through TMDb's find-by-external-ID endpoint, including after refresh. Other custom IDs need a compatible metadata add-on or an in-memory catalog preview.

TMDb is always the built-in metadata source for IMDb movie/series titles. There is no metadata selector. It selects the movie or TV result according to the catalog type. Series load the selected season first, then hydrate other seasons for the native episode drawer and preserve IMDb-based `ttID:season:episode` stream identifiers. Failed season requests show a retry state rather than generating demo episodes. Only ordinary TMDb responses use the existing TMDb cache.

`/addon/:addonId/title/:type/:id` shares `TitleDetails` with RainFlix titles, including logos, metadata, episode selection, and players on the right. Custom IDs use the owning or first compatible metadata provider internally; if none exists, the memory-only preview is used. Failures remain retryable without automatic provider switching. Home/Manage add-ons and metadata-source controls were removed from title pages. See [[Title Playback]].

Custom video IDs are preserved exactly in stream/subtitle endpoints, including colons and slashes. Series use the metadata's videos rather than inventing episode IDs. Live TV uses the channel identity. Inline video streams belong to the metadata provider and use the same explicit-Play handling as stream endpoints. The user selects a stream provider manually; video/provider changes unmount the prior player. My List and Continue Watching accept custom titles using minimal display summaries and detail/content/video identifiers, never complete responses or stream URLs. Catalog-only custom titles may need their catalog revisited to refresh metadata.

Supported capabilities now include catalog, meta, stream, and subtitles supplied by the selected stream add-on. Standalone subtitle-only, addon_catalog, EPG schedules, and arbitrary remote code are not implemented. Installing add-ons augments RainFlix without replacing the TMDb catalog. Browser CORS, codecs, proxy-header requirements, and torrent peer limitations still apply.

Add-on requests use the existing timeout/abort helper and no-store fetching. Installation failures remain retryable through the manifest input.
