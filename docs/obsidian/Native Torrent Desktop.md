# Native Torrent Desktop

Player subtitle, audio, speed and playback-settings popups use compact unframed layouts. Subtitle settings stays on the subtitle panel's heading row; speed choices use a two-column grid. Shared size, position and delay defaults are configurable from RainFlix Settings with a bundled-image subtitle preview. Remembered per-title appearance choices retain precedence. See [[Settings]].

## Episode Transition Safety

Native teardown remains registered after the active session is removed. Replacement playback waits for both pending startup and retiring player sessions before creating another embedded mpv surface. This prevents the old surface's WebView2 restoration from covering the new video during Next, automatic EOF, manual episode/source selection, or retry. Cancelling the replacement interrupts that wait; teardown has a bounded wait and failure returns to retry rather than opening a competing surface.

Browser fullscreen uses the stable document element so replacing an episode's portal does not implicitly exit fullscreen. Automatic episode/selected-source handoffs retain it; closing, manual stream selection, or leaving playback still exits. The shared handler recognizes only its own player container or this stable fullscreen surface. An outgoing episode's fullscreen/exit events cannot mark a newly mounted player's fullscreen entry and then close it when the old container exits.

Next/EOF is single-flight while a preload claim or episode handoff is pending. Repeated clicks and a simultaneous end-of-file event cannot trigger competing route changes or discard the claimed preload. An mpv decoder `end-file` error now reports failure immediately and closes the idle native surface so the browser retry controls are visible. These rules apply to all series and native media/torrent providers, not a title-specific override. Live source availability and torrent peers can still prevent playback.

Next-episode torrent selection stays on the active provider and requires the current known resolution and codec (HEVC/x265/H.265 and H264/x264 aliases are equivalent). It prefers a matching add-on `bingeGroup`, then the same torrent hash for season packs, preserving the next episode's own file index. Release hints remain in memory only. If no matching quality exists, Next opens manual stream selection instead of silently downgrading. Even without a completed preload, Next and known EOF successors use this same matching path. Track preferences remain per-title and are restored where the next stream supports them. An initialized claimed preload hands its existing local URL and cached pieces to the new player; it does not resolve a different source or discard those bytes. Decoder startup and missing peer data still mean this is not guaranteed gapless playback.

## Episode Drawer Updates

Native episode metadata is published immediately, before thumbnail downloads. The old 1,000-episode truncation could discard late seasons of long shows; the bounded list now retains up to 10,000 entries, prioritizing the selected drawer season if the bound is reached, then restoring chronological order for Prev/Next. Only up to 200 uncached images for the selected season are fetched per update, with the existing eight-second artwork deadline. Cached thumbnail paths remain unchanged across metadata updates. Monotonic revisions reject stale completions and closed sessions cannot receive updates.

Season selection requests the same title-page metadata callback on demand. The playing video's season remains distinct from the drawer's browsed season. Native rows have loading, empty, error/retry states; providers are selected before their streams, and an explicitly selected provider's sole playable stream starts directly. The native title includes local season and episode numbers. The artwork cap is not an episode-list cap: later rows remain selectable even without a downloaded thumbnail.

The Windows Tauri build has a **Native torrent** mode, selected by default for torrent results. Compatible direct HTTP/HLS sources, including HTTP video delivered by a P2P service, also use the same embedded mpv UI on Windows. The website keeps browser playback and its Browser WebTorrent default. P2P describes transport, not a distinct player; external-only URLs, unsupported schemes, DRM and proxy-header requirements remain limitations. Provider lookup only returns a source list. Choosing a source, or accepting the sole result after an explicit provider click, invokes playback. Entering a title, changing settings, or loading catalogs never starts a transfer.

The bundled mpv launch disables its stock OSC and OSD. The custom Lua overlay supplies RainFlix controls, with each ASS element emitted as a separate event line so its positioning renders correctly. WebView2 is hidden during native playback because its sibling window can obscure mpv. A `PlayerSurface` guard restores the webview, focus, and previous fullscreen state on normal close, cancellation, errors, and task teardown.

mpv disables its embedded child window by default. RainFlix locates only the child owned by its mpv process, enables input, and transfers keyboard focus using temporarily attached input queues. Mouse movement reveals controls; Space pauses, Left/Right seek ten seconds, and F toggles RainFlix fullscreen. Back and Escape (outside a panel) quit mpv directly, allowing the native monitor to restore WebView2 before reporting closure. Native torrents do not show the browser zoom/X overlay or a separate loading view. The native Back control remains usable during metadata resolution; errors return to an actionable browser message. The smoke script supports both actual Windows input and a separate render-only mode.

An installed playback session confirmed a startup race: mpv can disable its child after RainFlix's first enable call. The native monitor checks every 250 ms throughout playback and repairs disabled/recreated children. Enabled players also need keyboard focus recovery: the monitor checks the foreground thread's actual focused HWND, attaches the worker to both the app and mpv input queues, and focuses mpv only when RainFlix is foreground and focus is not already inside the player. It does not steal focus from other apps or repeatedly refocus a correctly focused player. Ctrl+Backspace while RainFlix is foreground stops the native player and restores the title page independently of Lua controls or WebView input. The smoke test deliberately disables the child after startup and also moves focus to the already-enabled parent before sending real Windows Space and Up keys without clicking the player; `-EmergencyExit` exercises Ctrl+Backspace instead of the Back control. IPC keypress tests alone only verify bindings, not Windows keyboard delivery.

## Custom Player UI

### Skipping And Up Next

The Windows native player has a Playback settings control (or S shortcut) with Auto-skip intro, Auto-skip outro and Next episode preview switches. Auto-skipping is off by default, so manual chapter Skip prompts remain available. The switches persist with the title's track preferences and follow the existing episode-resume flow. Only explicitly named OP/opening/intro and ED/ending/outro/credits chapters are skipped; there are no guessed timings. Each chapter is skipped at most once while staying in that chapter, only during active unpaused playback, never while a menu or buffering overlay is shown. Recap remains manual. The five-second startup/resume buffering threshold is unchanged.

Up next appears in the lower right during the last 30 seconds (or last 10% for short files), or within the final two minutes while an ending chapter is active. Its larger 540-by-204 layout uses a 208-by-117 thumbnail and wrapped title. It shows the next available metadata row's season/episode, title and cached thumbnail, falling back to title artwork. Clicking it uses the existing next-episode same-provider path, accepting an initialized preload when available even if warming is still underway. The preview itself does not authorize a download. Buffering and open panels hide it, and it is suppressed in very small native windows to prevent overlap. The manual Skip prompt moves above the preview. Native text has been increased another two points with adjusted episode-title truncation.

### Next Episode Preloading

Windows native torrent playback can preload the next known episode once the current video is playing without buffering; there is no percentage threshold or idle threshold message. Playback settings has a Preload next episode switch, enabled by default for native torrent playback; the choice persists with per-title track preferences. It never runs on initial title/catalog rendering or for browser/direct-URL playback, and explicitly future-dated episodes are excluded. It resolves only the current provider, matches the current quality/codec using the existing stream preference helper, and preserves torrent file indexes and trackers. A headless paused mpv demuxer warms five actual playable seconds (or accepts a confirmed cached end-of-file for short media), with a 32 MiB demux cache cap and 90-second warming deadline after torrent metadata resolution. Only one preload exists; its separate torrent engine is capped at 512 KiB/s, then paused once warmed. Slow peers or high-bitrate sources may not finish warming; normal next-episode lookup remains the fallback. The current player's five-second buffering wait is unchanged.

Rebuffering or seeking (while buffering), disabling the switch, choosing an episode's streams manually, leaving playback or changing sources cancels and deletes unclaimed preloads. Rebuffering cancellation has a 15-second cooldown before another attempt; explicitly enabling the switch clears that cooldown. An initialized preload is claimed only for Next, Up next or EOF advance; it gets a one-shot in-memory handoff, validated against magnet and file index. Claiming stops the hidden warmer without deleting the torrent engine or its cached pieces. The old player closes before the new player opens, so this reduces startup delay but does not guarantee a gapless decoder transition. An unused claimed preload expires after 30 seconds. The new session restores normal download limits and uses the already cached torrent pieces. Neither add-on responses nor credentials/stream URLs are persisted, and preloading never marks an episode watched. Cross-season preloading requires the next episode to already be present in native metadata.

### Scrollable Drawers

Opening the episode drawer (button or E) returns to the playing season and centers its episode in the visible rows. Centering waits for metadata when necessary and runs once per opening; wheel/arrow scrolling or a deliberate season change cancels pending centering so the list never repeatedly snaps back.

The native episode and stream drawers follow the title page's unframed list treatment: wider episode rows with 128-by-72 thumbnails, multi-line names and dates, and provider-first stream selection. Mouse wheel or arrow keys scroll episodes a row at a time; streams scroll in 80-pixel increments. Clickable scrollbars allow jumping through long lists. Stream rows preserve all label lines and wrap long filenames instead of truncating them; even an oversized row remains scrollable. A provider's sole result still plays immediately. Native Lua reproduces the React list styling rather than embedding a second WebView over mpv.

### Keyboard Shortcuts

These shortcuts belong to the Windows native player (third-party iframe players control their own keyboard handling):

- Space or K: toggle pause.
- Left/Right: seek backward/forward ten seconds; Shift+Left/Right: sixty seconds.
- Up/Down: volume up/down five percent, bounded to 0-100%; M: mute.
- N/P or media Next/Previous keys: next/previous available episode, using the existing same-stream handoff. No wraparound; unavailable adjacent episodes do nothing.
- `[` / `]`: decrease/increase playback speed by 0.25, bounded to 0.25-3x; Backspace: reset to 1x.
- C: subtitle menu; A: audio menu; E: episode drawer; S: playback settings; F: fullscreen.
- Escape: close the open panel first, otherwise leave playback.

While episode, season or stream lists are open, arrows page the list rather than seek or change volume. Other popups consume arrow shortcuts without changing playback. Space remains a deliberate pause toggle in menus. Speed, mute and adjacent-episode shortcuts are disabled while a panel is open. Repeated seek/volume/speed keys are supported; episode changes are not repeated.

The native Lua interface uses icon controls with hover labels, restrained charcoal surfaces, cyan accents, timeline buffer ranges and chapter markers. The Chapters button is removed. A manual Skip intro / Skip ending / Skip recap prompt appears only during an explicitly named matching chapter (including OP/ED), and seeks to the next chapter boundary or the file duration for the last chapter. There is no guessed timing or external intro database. Files without chapters have no skip prompts. The mpv decoder remains native; this is not a React overlay window.

Player labels are larger for readability. Skip prompts have a persistent translucent charcoal background, not just a hover highlight. Playback error messages offer Retry without an external Open torrent/Open stream action; explicitly selected external playback mode is unchanged.

Subtitle and audio labels resolve common ISO language codes, including Chinese Simplified/Traditional, Indonesian and Thai. The subtitle menu first shows an alphabetical language list with track counts and a separate Off row. Selecting a language opens its variants without activating or downloading a track; the Languages back control returns to the list. Embedded and add-on tracks share each language group. All variants remain accessible through paging, wheel and arrow navigation. Subtitle variants show their source, codec, hearing-impaired and forced-track flags when available. Appearance controls remain delay, scale and vertical position; these cannot resize image-based subtitle formats in the same way as text subtitles.

## Buffering Artwork

Next-episode preload status is visible above the timeline, in playback settings, and on Up next. Finding next stream and Connecting to peers do not invent percentages; Buffering uses the headless decoder's measured playable cache duration against its five-second target. Ready means that target or a confirmed cached EOF was reached. Failure, no matching stream and unsupported direct-URL playback are distinguished. The warm demuxer allows twelve seconds of forward read-ahead within the existing 32 MiB cap. Next/Up next/EOF can claim an initialized torrent even while warming: its hidden demuxer stops, the new player inherits the same torrent engine and disk pieces, and the download cap is lifted. It no longer discards a partial cache just because readiness has not arrived. This remains a new decoder transition, not guaranteed instant playback. If metadata has not initialized, normal fresh lookup still applies. A failed warmup is not reported as ready and Next retries normally.

During startup and rebuffering a small cyan accent travels smoothly beneath the title logo on a 3.6-second cycle, including while metadata has no measurable progress. It is an activity indication, not a guessed percentage. The logo fill still follows actual buffering and its raster remains cached; animation uses only lightweight ASS shapes. The accent is absent while paused or with a panel open.

Source clicks launch an idle embedded mpv surface immediately, before torrent metadata resolves. There is no separate React Back-and-logo loading screen. Rust fetches bounded PNG/JPEG/WebP title artwork asynchronously, avoiding browser image CORS, and updates the native artwork without restarting the player. The buffering background is the series/movie backdrop, never an episode still. Failed/missing artwork uses the RainFlix R fallback, not the episode title. The resolved video is opened through mpv IPC in that same surface. Closing during metadata resolution cancels both the native player and pending torrent work. No logo URL or add-on response is persisted.

The pending native surface can receive episode thumbnails and stream choices before torrent metadata completes. Replacement sessions wait for canceled pending players to restore WebView2 and finish teardown before opening another surface; this prevents late cleanup from covering the replacement video. Artwork and drawer metadata updates share the native state lock and reject canceled sessions.

Rust validates the raster dimensions/length, converts it to premultiplied BGRA, and creates temporary full-opacity and quarter-opacity bitmap files beside the playback metadata. A native surface guard deletes the bitmaps when mpv exits; the ordinary torrent-session cleanup removes the parent directory. `--force-window=immediate` allows the native overlay to appear while the file opens. Cache pausing is enabled, including initial buffering, with a five-second rebuffer target (EOF can resume earlier).

The logo is drawn inside mpv, not the hidden WebView2. It remains until a decoded playback restart and no cache stall/seek is pending, and returns during `paused-for-cache` or seeking. The left-to-right opacity fill follows mpv's `cache-buffering-state` (0-100), interpolated by elapsed time without advancing beyond the reported percentage. It is the playable cache target, not total torrent download progress. Raster logos now stay at a fixed size: repeated heartbeat resizing required redundant bitmap reads/scaling and caused visible stutter. Progress still updates at 30 Hz. Unchanged logo/background/thumbnail overlays are retained; ASS updates only when content or dimensions change. Unchanged metadata JSON is not reparsed every polling tick. A manually paused ready video darkens and displays the centered full logo without simulating buffering. The title backdrop appears only before the first decoded playback restart; later buffering/seek overlays show just the logo over the video. Menus temporarily replace the centered bitmap so it cannot obscure subtitle/audio choices. Back, controls and emergency exit remain usable during buffering.

The native smoke harness validates chapter prompts/seeks, subtitle labels and selection with local fixtures, and the bitmap fill at simulated cache states of 25% and 75%, plus clearing it when readiness returns. Live torrent stalls still depend on the chosen source. The browser suite checks bounded rasterization, alpha preservation, failures, cancellation and the artwork fetch timeout. `-SkipBuild` refreshes the Lua resource from source so UI edits do not accidentally test an old script.

`src-tauri/src/native_torrent.rs` embeds `librqbit` 9.0.1 (Apache-2.0). It uses conventional BitTorrent peers and DHT, plus valid HTTP(S)/UDP/WS(S) trackers from the selected source. The provided zero-based file index, including zero, is preserved. When no index is supplied, it chooses the largest supported video file. It downloads only that file, not every file in the torrent. Metadata resolution has a 75-second timeout. A single selected video must be at most 12 GiB; the session caps peers at 40 and upload at 256 KiB/s. DHT and torrent session persistence are disabled.

The engine serves the selected file on a random `127.0.0.1` port with an unguessable per-playback URL token. Only read-only media GET/HEAD routes are exposed, with byte ranges for seek. The URL exists in memory only. RainFlix attaches its bundled mpv video window to the Tauri main window with mpv's `--wid` option. `src-tauri/player/rainflix_ui.lua` draws back/fullscreen, seek, play/pause, volume, speed, embedded subtitles, audio tracks, and a paged season/episode drawer. The drawer receives bounded episode IDs, labels and thumbnail URLs, not stream responses. All declared seasons are hydrated; thumbnail bitmaps update asynchronously without restarting playback. Prev/Next resolves a similar stream from the last provider automatically. Clicking a sidebar episode instead opens fresh stream choices in that same native drawer; Back returns to episodes without stopping the current video. Native stream metadata contains labels and opaque IDs only; React retains playable URLs in memory. Request IDs prevent late choices from replacing a newer episode's lookup. `--window-dragging=no` and `--input-builtin-dragging=no` prevent moving the embedded video window. There is no cast control yet. mpv's IPC events return to `AddonPlayer`; Continue Watching starts only after mpv reports playing. Close, source/provider/episode changes, stop, and app exit stop mpv and cancel the torrent session, deleting owned temporary artwork and playback directories. Another RainFlix process's cache is not swept at startup. An abnormal crash may leave a playback directory behind; safe stale-cache cleanup needs a future ownership/locking design.

The desktop installer includes the mpv/FFmpeg decoder, so video no longer depends on WebView2 codec support. Torrent file selection recognizes MP4/M4V, WebM, Ogg, MKV, AVI, MOV, MPEG, TS/M2TS, WMV, ASF, FLV, and 3GP; explicitly indexed files with other extensions are handed to mpv for probing. Most ordinary codecs and embedded subtitles should work, but DRM, damaged files, unusual formats, and torrents without peers can still fail. Installed subtitle add-ons now appear in the same native menu; selected uncompressed subtitle files are fetched with a ten-second timeout and 4 MiB limit into temporary playback storage, then loaded through mpv IPC. Failed results do not block other providers. URLs stay in memory, not native metadata. See [[Subtitle Add-ons]]. There is no transcoding, casting, or protected credential storage. Registrations persist privately in IndexedDB. Stremio Service and external torrent app modes remain manual alternatives.

`npm run desktop:prepare` downloads a pinned first-party mpv Windows build, verifies its archive and executable SHA-256 hashes, and places `mpv.exe` plus `LICENSE.GPL` in ignored `src-tauri/binaries/`. `desktop:dev` and `desktop:build` run this preparation automatically; the installer bundles the decoder and `rainflix_ui.lua`, so users do not install mpv themselves. This mpv build is GPLv3 and substantially increases installer size. Review the GPL and corresponding-source obligations before public distribution. The website build does not include mpv.
