# Title Playback

Web playback (including trailers) has no RainFlix fullscreen/close overlay buttons. Browser Back or Escape closes playback through the history entry or `rainflix:close-playback`; native app controls remain available. The website lists RainFlix App / Free streams and marks Yastream as Free stream. Empty add-on results use one message rather than one line per provider. Mobile selection hides More like this together with the synopsis. Hero image variants are predecoded and the outgoing reduced-motion image remains opaque until the new one covers it; ambient backgrounds use the same cover-first crossfade.

Mobile provider/episode/source selection hides the title synopsis while the selection step is active and scrolls the Streams panel into view; Back restores provider selection. Android retains bottom play/pause and five-second seek controls alongside center controls. Windows has explicit five-second seek buttons alongside keyboard seeking. Trailers request fullscreen immediately, disable YouTube's fullscreen action (`fs=0`), and omit RainFlix's redundant fullscreen button. Android trailer and native playback hide system bars and use camera-cutout space; leaving restores portrait catalog insets.

Android and Windows stream selection now force native playback and omit the obsolete Torrent Playback mode selector. Browser-only private routes retain browser/service options. Quality badges include upstream-reported peer counts when supplied in structured fields or source labels; they are not live connected-peer measurements. History cards have no ellipsis button: right-click, keyboard menu key/Shift+F10, or a 600 ms touch hold opens RainFlix's history menu. Movement cancels a touch hold. Browser context menus are suppressed globally, without blocking normal clicks or the app's history menus.

Native global defaults now come from [[Settings]]: preferred track languages, automatic intro/outro skipping, next-episode prefetch, preview and automatic next. Explicit remembered per-title track choices remain supported. Android warmup and marker/timing limits are documented in [[Android Native]].

Title-page stream and episode lists allow wheel/touch scrolling to pass through to the page when they reach their upper or lower edge. They retain bounded scrolling and do not add custom scroll-blocking gesture handlers. See [[Navigation]]. Normal ambient artwork is blurred on both crossfade layers; featured thumbnails and playback stay sharp.

In-player provider/source lists now share add-on logo metadata and compact stream headings, quality badges and full release details. Android uses the HTTP(S) logo with an R fallback; Windows decodes bounded provider artwork into session-owned BGRA overlays, with a letter fallback if unavailable. Logo fetching is optional, capped at twelve providers and does not delay the initial source list. Source dividers and smaller detail text keep long torrent descriptions readable without truncating them. The Android-only gesture, language picker and subtitle appearance changes are documented in [[Android Native]].

Automatic TMDb season-group discovery applies to every series through the shared metadata loader, including native and IMDb add-on title pages, season navigation, the native episode drawer, and next/previous/preload selection. Only validated season-type groups that split the default seasons and preserve every original regular episode in order are chosen; no title is hardcoded. Group episode order becomes local SxxEyy stream IDs. Original TMDb season/episode coordinates remain separate metadata aliases and progress keys. Specials remain excluded as in ordinary TMDb metadata. Unsupported, incomplete or unavailable groups fall back to the original season list. The chosen group and original season counts travel with loaded metadata so later season requests use the same ordering. See [[Configuration]] for optional overrides and the automatic-grouping switch.

## Automatic Episode Continuation

Actual browser video `ended` or native mpv EOF advances series to the next available episode, using the existing fresh-stream resume path and remembered provider/quality/track preferences. It does not advance at the approximate Watched threshold. The shared metadata loader checks the current season and then later seasons, ignoring explicitly future-dated episodes. At the final episode (or if next-season metadata fails), playback closes back to the series title page. Native EOF followed by process closure is handled once so closure cannot cancel continuation. Back/close cancels a pending metadata lookup. Movie and trailer end behavior is unchanged.

For native Windows torrents, the per-title Preload next episode switch authorizes a bounded same-provider lookup and five-second startup warmup once the current video is playing without buffering. There is no playback-percentage threshold. An initialized torrent (including one still warming) uses a validated, single-use memory handoff on EOF, Next or Up next; otherwise continuation still resolves fresh. Player controls, settings and Up next show lookup, peer connection, measured buffer progress, readiness or failure; no idle threshold message is displayed. Preloading does not record playback history. Manual sidebar episode selection cancels it and continues to provider/source selection. See [[Native Torrent Desktop]] for rate limits, cancellation and temporary cache ownership.

## Official Viewing Services

The title-page Streams list shows regional official services first, followed by available add-on providers, in one shared scrolling panel without a separate official-services heading or container. Add-on provider rows use HTTP(S) manifest logos with the same 40px logo sizing and row spacing as official services; missing or failed logos fall back to the RainFlix R. Netflix, Crunchyroll, and other providers appear only when returned by TMDb's `/movie/{id}/watch/providers` or `/tv/{id}/watch/providers` metadata. Native and IMDb-matched add-on titles share this; unmatched custom IDs do not guess official availability. For series, Streams providers appear first; choosing an add-on opens Episodes, then choosing an episode opens that provider\'s source options (or directly plays its sole playable stream). Back moves from options to episodes to providers. Provider selection survives season loading; no series stream lookup occurs before choosing an episode. Continue Watching remains an explicit remembered-source resume action. Official rows do not appear inside the episode selector or source-selection view.

Country detection calls `https://api.country.is/` once per app session with no credentials, referrer, or persistent cache. This external service sees the request's public IP; RainFlix does not store the returned IP or country in localStorage. A three-second timeout or blocked/failed lookup falls back to an explicit country in the browser's language tags. There is no country selector or hardcoded Philippines/US availability default. If neither source supplies a country, availability stays unknown instead of claiming a guessed region. VPNs affect the detected country. Detection runs again after reload; any obsolete saved `rainflix:watch-region:v1` choice is ignored.

Availability is fetched fresh without persistent caching, with a ten-second UI timeout and Retry on failure. Subscription, free, ad-supported, rental and purchase offers are merged into one row per provider. Series availability is title-level, not a promise that every season/episode is available. Empty countries show an explicit empty state, never fabricated services. Add-on lookup errors do not prevent official rows from appearing in Streams. When no add-on providers are installed, the generic no-add-on-streams message is hidden; configured provider failures retain their status and Retry.

TMDb supplies an official viewing-options page, not provider deep links or playable URLs. Each service row opens that trusted TMDb HTTPS page in a new browser tab (or the desktop external browser), where official service links are available. These links never launch RainFlix playback, update Continue Watching, or replace remembered stream preferences. The country/availability attribution footer is hidden in the Streams list; regional detection still determines which services appear.

## Remembered Playback

Continue Watching advances series episodes at 90% of their runtime, including longer episodes with more than two minutes of credits remaining. Progress is saved during playback and on native player Back/close; leaving earlier resumes the same episode. Movies retain their existing 95% or 90%-with-at-most-two-minutes-left completion rule. This is a runtime-based credits heuristic, not exact credits detection. It changes the Home resume target, not playback itself: automatic Next still requires actual EOF or a user action. Startup applies the same series-specific threshold to previously saved progress. Known remaining episodes advance the series card; fully watched known series leave Continue Watching for the grouped Watched section.

Continue Watching links include `resume=1`, an explicit playback action. The remembered provider is queried fresh; RainFlix prefers its last resolution/codec and never stores signed media URLs or torrent responses. Missing providers do not silently fall back to a different provider. Ordinary title-page episode selections always return to stream selection. Only Continue Watching and the native player's Prev/Next controls automatically reuse the last source preference. Native mpv saves/restores audio and subtitle language/variant choices plus volume, speed and subtitle appearance in the separate bounded `rainflix:playback-preferences:v1` store. Compatible browser subtitles also remember the selected language. My List and Continue Watching summaries persist on the device.

Native Windows torrent playback uses the mpv Lua controls exclusively, without the browser zoom/X overlay. A Back action cancels lookup/loading/errors. During video playback, the enabled mpv child owns mouse and keyboard input; Back or Escape exits locally and restores the RainFlix title page. See [[Native Torrent Desktop]].

Ctrl+Backspace is a native emergency return while RainFlix is foreground, even if the overlay/input handoff fails. The native monitor continuously repairs mpv's late-disabled child window.

Native playback now carries a bounded title-logo raster into mpv for startup/rebuffer artwork; filling follows the playable cache target, not the torrent download percentage. The Chapters button is removed; contextual chapter-based intro/ending/recap skip actions remain when those boundaries exist in the file. See [[Native Torrent Desktop]] for readiness, language labels and temporary-artwork cleanup.

Related: [[Architecture]], [[Add-ons]], [[Configuration]], [[Troubleshooting]].

## Navigation and Metadata

RainFlix cards, search suggestions, and More Info actions now open `/title/:mediaType/:id`. There is no preview modal or separate watch layout. `WatchPage` redirects old `/watch/...` links, preserving the selected season and episode. Old `?preview=movie-ID` links redirect too.

`TitleDetails` is shared by native TMDb titles and `/addon/:addonId/title/:type/:id`. IMDb add-on titles always resolve through built-in TMDb metadata. Custom IDs use the owning or first compatible installed metadata provider internally, then a catalog preview only when no provider exists. Provider failures show Retry rather than silently switching. Custom IDs must never be passed to the iframe URL builders.

The title uses its artwork logo when available, falling back to text on missing or broken artwork. My List, Share, and Play trailer share the title action row. Cast/company/genre links remain available. Similar titles use `RelatedCarousel`, a responsive horizontal scroll-snap row without arrow buttons; touch, trackpad, and keyboard focus can navigate it. Both TMDb and custom titles can be saved and enter Continue Watching, using bounded display summaries and IDs rather than complete add-on responses.

`EpisodeList` is the first step inside the right-hand playback panel for series (below details on mobile). Season navigation and episode search stay above bounded scrolling rows. Choosing an episode shows available Streams, even after another episode has played; Back to episodes returns to selection. Rows use TMDb stills/air dates or add-on thumbnails/release dates when available; missing artwork has an icon fallback. Episode descriptions stay hidden. History records only actual playback. Search applies to the selected season and clears on season change. Movies without episode/video choices open at Streams.

## Selecting Playback

`TitlePlayers` lists available installed streaming add-ons after episode selection. Built-in iframe providers have been removed; optional Yastream/Torrentio adapters remain disabled by default. Nothing streams on title entry. `TitlePlayers` performs cancellable availability lookups first, listing only providers returning sources and displaying a loading state while pending. `AddonSources` reuses that in-memory lookup on explicit provider selection, or resolves fresh URLs on Retry/Refresh. During lookup, the provider list is replaced by the pulsing title-logo loader, with no visible loading text or spinner. A Cancel stream lookup arrow aborts the lookup and restores the provider list and focus. Refreshing an existing source list also shows only the logo in the source area until the request finishes; loading labels remain available to assistive technology. Multiple results replace Streams with a bounded scrollable sources view. Its Back arrow returns to Streams, cancels pending lookup, and restores focus to the provider. Multiple results wait for a source click. A fresh lookup with exactly one playable result opens it directly without ever showing the stream list or its Back navigation; closing returns to Streams. An external-only/blocked result, empty result, or lookup error still shows a source panel for actions/settings/retry. Refresh fetches fresh URLs. There is no automatic provider fallback.

`AddonPlayer` receives a single selected source and starts the existing MP4/HLS/WebTorrent/Stremio engine, or [[Native Torrent Desktop|the desktop torrent engine and embedded mpv window]]. Native sidebar episode selections replace the episode drawer with fresh stream choices in the same native container, without returning to the title page. Only labels and opaque choice IDs enter native metadata; the actual streams stay in React memory. A one-shot module-memory handoff moves the selected stream into the next episode; history carries only its opaque token. Prev/Next automatically attempts a freshly resolved similar stream. Closing, navigating, switching providers, or changing episodes tears down the video/native player, torrent session, HLS instance, timers, subtitle fetches, and listeners. Lookup responses, source URLs, and playback descriptors are not persisted.

Torrent mode and local-service settings stay in the pre-play source panel. Changing a mode or connecting a service never starts a transfer. Connect only requests `/settings`; a source button (or a sole-source launch after a provider click) authorizes media transfer. External launches never count as watched.

## Fullscreen

Streams and the manual Play trailer button open the same edge-to-edge overlay. There is no playback header. Close and fullscreen icons auto-hide, returning on pointer/keyboard interaction or focus. Native subtitles are selected through the captions menu inside the video, not an external dropdown. Iframe controls remain owned by their provider.

RainFlix requests the Fullscreen API from the click when possible. Browser policy may deny native fullscreen after asynchronous source lookup, so a full-window overlay is always available, with a fullscreen icon for another explicit attempt. The Windows native torrent player instead attaches mpv to the main window and toggles Tauri fullscreen from its own controls. Native video attempts autoplay; browser audio policy and iframe behavior still apply.

Playback pushes a non-secret `play=1` history entry. Back, Escape/remote Back, or Close stops playback and restores title details. Refresh/Forward never restores an active stream automatically. A direct popstate listener stops media even when React coalesces rapid route transitions. The background app is inert during playback, and focus returns to the launching control.

Continue Watching records native media only after `playing`. Iframes keep the existing validated playback-message/interaction tracking. Trailers never enter Continue Watching.

## Buffering Artwork

More like this uses plot/keyword TF-IDF cosine similarity plus weighted genres, language, companies, cast, crew and directors, with Bayesian rating confidence and minimum-vote filters. More opens a scroll-loaded recommendations catalog. See [[Recommendations]] for weights, request bounds and limitations.

Native manual Skip intro/ending prompts share the player controls' visibility and hide timer. Android follows Media3 controller visibility; mpv follows its four-second control-activity clock. Touch/mouse/key control reveal also reveals a valid skip prompt. Automatic skipping is independent of prompt visibility. Unknown duration or absent metadata provides no skip. Both players reject chapter ranges longer than five minutes or one quarter of the video, intros outside the opening region, and endings before 65% of runtime. Whole-episode intro labels are never skippable. These conservative guards apply to manual and automatic skipping; unusually long legitimate openings may consequently have no skip action. Tests: `ChapterSkipGuard`, `PlayerUiTest`, and `scripts/verify-skip-prompt.lua`.

Subtitle language, subtitle variant and audio menus are scrollable without page navigation. Playback/episode URL updates replace the current title entry, so closing playback returns to title details instead of retracing every source or episode change. See [[Navigation]].

On web title pages, RainFlix App is the first Streams entry, before official availability. The title action row starts with a blue Watch on RainFlix App button, before My List, Share and Play trailer. Both link to Downloads in the current tab; native app title pages omit this download action.

The native episode drawer loads a selected season through the same `getTmdbTitleMeta` callback used by title pages, without changing the playing episode. It includes a clickable season selector, previous/next season controls, loading/error/retry states, and episode -> provider -> stream selection. A provider with a sole playable result starts directly after its explicit click. The playback heading includes local season/episode numbers (`S23 E1`) and the episode title.

Missing or failed title logos use the bundled RainFlix R artwork, including the native player's initial loading and pause overlays. The title page uses provider -> episode -> streams. The Android player uses episode -> provider -> streams: selecting an episode shows compatible installed providers immediately, and an explicit provider click requests only that provider. A sole result plays immediately; empty results offer Retry. Back returns to providers, then episodes. URLs stay in the frontend's per-request memory; only opaque choice IDs, provider names, and stream labels reach the native menu.

Cross-season navigation must not render the previous season's metadata against the new route. `TitlePage` keeps the loading state until metadata matches the requested season, preventing a stale render from consuming the one-shot stream handoff. A resolved canonical IMDb episode can be accepted before the React episode-list state commits. EOF followed by a native closed event must not cancel the pending next-episode handoff.

Windows compatible HTTP/P2P video and torrents now share the embedded mpv UI. Its title backdrop is startup-only; later stalls show the fixed-size progress logo over the video. Raster heartbeat scaling was removed to avoid repeated resampling. Independent installed subtitle providers are merged into the captions menu after source selection; see [[Subtitle Add-ons]]. Browser playback remains unchanged except that later buffering no longer reintroduces the poster.

`PlaybackLoader` displays a dim title logo with an opaque left-to-right reveal. Missing/broken logos fall back to the RainFlix R image. Browser MP4/HLS/torrent video uses the browser's actual contiguous buffered range ahead of the playhead, targeting up to eight seconds (or the shorter remaining duration). This is playable-buffer readiness, not total-file download progress. `canplay`/`playing` hides the indicator without inventing a 100% value; a later `waiting` event measures it again.

The whole logo has a subtle, slow double pulse over 3.6 seconds, independent of the measured fill. Waiting for metadata, unknown duration, or an iframe's initial load shows only the faint pulsing logo, never a simulated filling sweep. Reduced-motion disables the pulse and fill transitions. Cross-origin iframe buffering after initial load remains controlled by the provider.

During native add-on buffering, the video surface, built-in controls, and captions menu are hidden without unmounting or restarting the media. This prevents the browser's own loading indicator from showing through the logo overlay. Controls return when the video can play; Close/fullscreen controls and actionable error/retry messages remain available.

## Watched History

Continue Watching cards on Home and My List offer a context menu (right-click, Shift+F10, or the history-options icon on touch devices). It supports opening a title in a new tab, marking the whole title watched, and removing it from history. Manual Mark as watched uses `markTitleWatched`: it removes the movie or entire series from Continue Watching immediately, clears that title's saved positions, and persists a `markedWatched` flag so unknown or remaining episode counts cannot reinsert it. It appears once in Watched, even if season counts are unavailable. Startup and cross-tab storage changes reconcile stale Continue Watching entries against these manual marks. Starting actual playback again clears the manual mark and begins a new Continue Watching entry. Automatic playback completion still uses `markWatched` for individual episodes and advances unfinished series; it does not mark the entire series manually. Removal clears only that title's saved positions, not other titles or My List. Watched storage is grouped by title, bounded to 200 titles, with deduplicated season/episode pairs retained internally for series. My List displays one Watched card for a completed movie or fully completed series, never one card per episode. Marking a completed series unwatched resets its whole watched history and returns it to Continue Watching at the first known season's episode 1.

After actual playback starts, series episodes are marked watched at 90% of runtime; movies use 95%, or at least 90% with no more than 120 seconds remaining. Actual `ended` also counts. Movies leave Continue Watching on completion. Series stay there, pointing to the next unwatched episode when known, until every episode in all known regular seasons has been marked watched. Skipped episodes are not inferred as watched; specials do not gate regular-series completion. Unknown season counts conservatively keep a series unfinished. Playback supplies count summaries in the displayed season order and transient episode metadata for resolving the next ID; no stream/add-on responses are persisted. Provider-defined episode IDs are never guessed. Later playback with updated season counts reopens completion when new episodes exist. A stale completion cannot overwrite a different episode currently in Continue Watching. This remains a duration-based estimate, not detected credits or verified attention; seeking near the end also counts. The player keeps running through credits, but future playback of a watched episode starts from zero. Trailers and external launches are excluded. Existing stream preferences and My List remain intact.

On startup, legacy per-episode Watched records are deduplicated into title summaries. Unfinished legacy series missing from Continue Watching are restored there once; deliberate history removal is respected on subsequent restarts. Existing Continue Watching records whose saved playback sample already meets the completion rule are reconciled once, advancing unfinished series instead of dropping them. No provider requests or playback are started by migration. Old records lacking season counts cannot prove whole-series completion until fresh playback metadata supplies those counts.

## Playback Positions

Regular TMDb seasons use season-local episode numbers starting at 1, including title-page routes, provider requests, the native sidebar, and next/previous navigation. Source-number gaps are preserved rather than shifting later episodes across a missing entry. Original TMDb episode numbers remain metadata aliases for old links and stable progress/preference keys, so saved timestamps still match the same episode. Specials and custom add-on video IDs keep their provider-defined numbering.

`src/lib/playback-progress.js` stores timestamps in seconds, keyed by title and season/episode rather than provider or stream. TMDb/IMDb identities use `rainflix:playback-progress:v1` in localStorage, bounded to 200 entries. Only the content key, position, duration, completion flag, and update time are persisted, never source URLs, credentials, or add-on responses. Custom add-on identities also persist bounded positions; live channels and trailers are excluded. Add-on registrations now persist in IndexedDB; see [[Add-ons]]. Clearing Continue Watching also clears saved positions.

Native video records only after `playing`, keeps current samples in memory, and writes at most every five seconds during playback. Pause, completed seeking, page hide/backgrounding, and player cleanup flush the final sample before media resources are destroyed. A source/provider click snapshots the saved timestamp; the next native player seeks after metadata arrives (retrying when it can play). Finished videos restart at zero. A saved position beyond the new stream's duration also restarts at zero. Different cuts/editions can still have different timelines. Browser storage is per-device and per-origin, not account sync; unavailable storage falls back to memory.

Trailer iframes do not store positions or enter Continue Watching. Built-in iframe providers have been removed from selectable playback; native add-on media retains the shared position and resume behavior described above.
